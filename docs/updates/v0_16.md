# ahpd 0.16

> ## The good stuff
>
> ahpd speaks AHP 1.1.0, a chat runs on an agent of its own, a running command moves to the background, and automations run once or continue a chat.
>
> - [AHP 1.1.0](#ahp-110): reasoning times, files being edited, and a moved chat that says where it went.
> - [A chat on its own agent](#sessions-and-chats): Claude, cofold, pi and ACP side by side in one session.
> - [Move a running call to the background](#agent-tools): Ctrl+B, from a client.
> - [Automations](#automations): run once at a set time, continue a session or one chat, and delete with the sessions they made.
> - [Claude](#claude): MCP servers' skills, typed answers to questions, and the right cost after a resume.
> - [Machines](#machines): a released host's own ahpd in machines and on boxes, a copy for a box with no internet, and dev containers from an image.
> - [Usage by tag](#usage): label agents, logins and connectors, and sum by label.

## 0.16.0-rc.1 - unreleased

### Upgrading

- A blank in an edit of a bot clears the field: `description`, `instructions`, `template`, `provider`, `model`, `preset` or `computer`. It kept the old value before. Leave a field out to keep it.
- A change of a bot's agent or model reaches its open talks: the next message starts a work chat on it, without the conversation before. Set the bot plugin's `agentChange` to `keep` for the old behaviour. See [Bots](../plugins/BOTS.md#the-back-a-message-wakes).
- A make of a bot that names no folder is refused `-32010` where `<root>/<slug>` already has files. It wrote the bot's parts into an `AGENTS.md` there, which could be another host's bot. Name the folder as `workspace` to take it. See [The folder](../plugins/BOTS.md#the-folder).
- A create that names no agent can run on another agent than before. The host takes its default agent, or with none set the first one that is on and whose program is found. It took the first one loaded. Set the root config key `defaultAgent` to choose. See [Root config](../sdk/HOST.md#root-config).
- A bot and a push device change by commands only. `resourceWrite` and `resourceDelete` on `bot://` and `push://` are refused, and the message names the command: `x-ahpd/bots/put` and `x-ahpd/bots/remove`, or `x-ahpd/push/put` and `x-ahpd/push/remove`. Reads, lists and watches stay. See [Bots: commands](../plugins/BOTS.md#commands).
- A Claude agent with `sandbox: on` asks before a sandboxed Bash command, where it ran one with no question. Under `dontAsk` the command is denied. Set `autoAllowBashIfSandboxed` on the agent's record to keep the old behaviour. See [The record](../plugins/agent-claude.md#a-record-of-the-engine).
- pi and cofold run commands in the host's shell by default: a terminal a person can watch and type into. Set the root config key `enableCustomTerminalTool` to `false` to keep their own. Windows is unchanged. See [An agent's own shell](../sdk/TERMINALS.md#an-agents-own-shell).
- A cofold agent reads the harness configuration under cofold's names only. Move `~/.config/copapo/config.json` to `~/.config/cofold/config.json`, rename `.copapo.json` to `.cofold.json`, and rename the `COPAPO_*` variables to `COFOLD_*`, such as `COPAPO_CONFIG` to `COFOLD_CONFIG`.
- A cofold or copapo machine made before this release finds no providers, because its state volume holds `copapo/config.json`. Remake the machine.
- A run of an automation that continues a session waits in the chat's queue when a turn is running, and every run is `pending` until its turn starts. `overlap: steer` no longer steers such a chat. See [Where a run goes](../sdk/AUTOMATIONS.md#where-a-run-goes).
- While a session runs a turn, the host keeps a machine on mains power awake. Set the root config key `keepAwakeWhileWorking` to `never` to let it sleep, or to `always` to hold on battery too.
- A client that answers nothing for 30 s is closed: a `ping` request goes out after 10 s of silence, and any data from the client starts the wait again. A client must answer the request; a refusal as an unknown method is an answer.
- A dev container that is stopped is started again only by a connect that says `resume: true`. A client that reconnected to a stopped one sends it. See [The surface](../plugins/CONTAINERS.md#the-surface).
- `@ahpd/computer` runs on `@ahpio/sandbox-runtime` 0.0.83, ahpio's fork of Anthropic's runtime, and needs Node 22.12 or later. On Ubuntu 26.04 the AppArmor profile `bwrap-userns-restrict` stops it; the sandbox check says so and names the commands that unload the profile.
- A Claude turn after a resume could be charged the session's whole spend again. New turns are right. To correct records an older host wrote, stop the daemon and run `scripts/repair-claude-usage.mjs` from a checkout. See [Repair Claude costs](../server/USAGE.md#repair-claude-costs).
- An ACP session whose agent cannot start fails its creation with the agent's own words, where it read as ready and failed its first turn.

### AHP 1.1.0

- Every package is on `@microsoft/agent-host-protocol` 1.1.0. A client that offers 1.1.0 agrees on it, and an older one is served as before. See [AHP compatibility](../sdk/AHP.md).
- A reasoning part says when it started and how long it took, live from every agent. A restored chat has the times its log gives: both from cofold, the start alone from pi, and none from ACP.
- A changeset file says `Editing` while an agent edits it, and carries a `nonce` that moves with its content. An operation that names an old nonce is refused with `-32011`, and the changeset is sent again as it is now.
- A chat that moves to another session says `chat/moved`, so a client with it open follows.
- `resourceRead` honours `position` and `length` for a file and answers its `size`. `initialize` says the host's `environment.pathStyle`. `authenticate` keeps the `accountId` it is given and refuses an empty one.
- A session's annotations channel is named on the session and its row. `<session>/annotations` still works. A canvas says `uri`, with the same value as `url` beside it.

### Sessions and chats

- A host has a default agent, the root config key `defaultAgent`, for a session, an automation, a tool or a bot that names none. With none set, an agent whose program is missing is passed over.
- `createChat` takes a `provider` and makes the chat on that agent, with that agent's own settings. Such a chat can move to a session of another agent and keeps its own. It is on by default; the root config key `multipleChatProviders.enabled` turns it off.
- A new chat can have a workspace of its own: a folder, a new worktree, or a scratch folder. A chat that has not started can be given one later.
- A session with one chat moves under another session with `vscode/moveSession`, and the chat keeps its turns.
- A session is made from a conversation sent by the client. Claude, pi and cofold write it as their own history and resume from it.
- `vscode/importSession` restores an external session and adopts it.
- Each chat lists its own changes: Branch, Uncommitted, This Turn and Compare Turns. "This Session" counts the files a shell command wrote, and a folder with no git has counts. Uncommitted changes show during the first turn.
- A worktree that could not be removed is tried again, after a restart too, and a client can list, measure and clean the worktrees the host made. See [Worktrees the window manages](../sdk/AHP.md#worktrees-the-window-manages).
- Create PR pushes to the branch's own push remote and finds a fork's open request.
- A client plugin announced again with a new decision moves in the session's list. A decision a person made in the session stays.
- A chat served by a nested host names its changes so that the outer client can open them.
- A session file that cannot be read stays in place and is listed as a failed session, where it was dropped. A delete removes the file.

### Agent tools

- A running command moves to the background with `x-ahpd/backgroundToolCall`, as Ctrl+B does in Claude Code. The call is answered, the command goes on as a background row with a stop, and the agent is woken with its output. It works for the host's shell and for Claude's own commands and subagents. ACP calls cannot move.
- A shell command that asks for a password can ask the person: `sudo`, `ssh` and `git` prompts go to the client, and the answer is never logged. It is off by default, behind the root config key `shellAuthentication`, and only for commands on this host.
- `create_session` takes `reasoningEffort` and `contextTier`, behind `sessionModelOptions`, and a new chat takes the calling chat's whole model selection. `add_artifact_or_reference` takes display options, behind `chatResources`. Both keys are off by default.
- A client runs its own tool only once the agent has started the call. A fast client could run one before its question was put, and the turn then waited forever.
- A client's tool call that waits for approval is declined once the client is gone.
- A permission rule `Mcp`, `Mcp(<server>)` or `Mcp(<server>/<tool>)` matches an MCP call.

### Automations

- An automation runs once at a set time, with the `oneTime` trigger.
- `target` says where its runs go: a new session, the session of the last run, or one chosen chat. See [Where a run goes](../sdk/AUTOMATIONS.md#where-a-run-goes).
- `vscode/deleteAutomation` deletes an automation, and with `deleteHistory` the sessions its runs made.
- When an MCP server of a run needs a sign-in, the host asks the owner's clients for a token they already hold.

`oneTime` and `target` are AHP 1.2.0's, taken early. Their shape can change until 1.2.0 is published.

### Claude

- A session lists the skills each of its MCP servers serves, under the server, and a person turns each one on or off until the daemon restarts. A server in a plugin, and one of a session in a machine, is not asked. See [Skills an MCP server serves](../sdk/AHP.md#skills-an-mcp-server-serves).
- An MCP server that is still connecting when the session starts no longer stays at `starting`.
- A question takes a typed answer beside its options.
- A lowercase `bash` call runs the shell. A model that wrote it had the call refused.

### Machines

- A host installed from a release runs its own version of ahpd in its machines and on its ssh boxes. It ran an older release before. A host run from a checkout runs the version committed there.
- An ssh box that cannot download ahpd, and has no install that runs, is sent the files by its host, about 80 MB over ssh. A box with an older install keeps running it. See [The ahpd on the box](../plugins/COMPUTERS.md#the-ahpd-on-the-box).
- A dev container starts from an image, with no folder on the host, and its workspace is a volume. See [A container from an image](../plugins/CONTAINERS.md#a-container-from-an-image).
- A dev container keeps the user's state (`.config/ahpd`, `.claude`, `.pi` and `.config/cofold`) when it is made again, and is made to run the sandbox when `sandboxEnabled` is on.
- A dev container that a session runs in is not stopped or removed by a client, whichever way the session was placed in it.
- A chat whose sandbox allows the whole network reaches every host and keeps its file rules.

### Bots

- An edit of a bot's agent or model reaches a talk that is open, and a blank puts a field back to its default. An edit did neither.
- A new bot never writes over a folder that has files, such as a bot of another host that shares the root.
- Each chat of a bot session keeps its own log, so it opens with its own turns after a restart. Logs mixed before this release stay mixed.
- An `owner` edited by hand in a bot's file is taken while the daemon runs, and the log says so.

### Daemon

- `ahpd configure` asks with lists to pick from, offers the agents found on the machine, and can install one that is not there.
- In a container, the default plugin is no longer installed again on every start.
- The root config declares the keys VS Code main added. Most are kept and do nothing yet.
- A minted token that asks to manage tokens is told that a minted token cannot, where it read which grant it lacked.
- A client can report how long a turn took to answer, exported as traces, behind the root config key `diagnosticTiming`.

### Usage

- Agents and connectors take `tags`, and a usage record carries the tags of what it passed through. `usage://groups?by=tag` sums by tag, and `tag=a,b` keeps the records with every tag named. See [Groups](../sdk/USAGE.md#groups).

### SDK

- A plugin declares a list with `registerList`, and any plugin adds a kind of record to it with `registerKind`. The host serves the list as a channel and asks the kinds for their rows. See [A list of your own](../plugins/PLUGINS.md#a-list-of-your-own).
- `Session.sendBringsUp` announces a session ready only once its first message has reached the agent, and fails its creation otherwise.
- A channel a plugin registers can offer operations to `x-ahpd/invokeOperation`, with `operations` beside its `snapshot`. It is for a list one plugin serves, and its operations name no kind. See [A channel of your own](../plugins/PLUGINS.md#a-channel-of-your-own).
- An `Agent` may answer `missingProgram`, the program it needs and cannot find. `onPath`, the lookup behind it, is exported from `@ahpd/sdk`.
- `launch`, which starts npm on every platform, is exported from `@ahpd/sdk`.
